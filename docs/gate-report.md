## What each number is not evidence for

- **E1 — exact-match precision** — Labels are generated, not hand-labelled. The generator derives brand and article type the same way the matcher does, so an error shared by both is invisible here. This measures matcher behaviour given correct fields, and guards against regression; it is not the Phase 1 exit evidence.
- **E1 — silent variant substitution** — Fuzzes stock and query against the nine committed wishlist items. It does not vary the wishlist itself, so a substitution that only occurs for a saved item shape absent from this fixture would not be caught.
- **E2 — query field accuracy** — Queries are assembled from catalog values, so they are well-formed by construction. Real queries carry typos, plurals, slang and brand misspellings that this set contains none of; treat the number as an upper bound.
- **E3 — match latency** — In-process JavaScript on one machine with the catalog already in memory. It is not the 500 rps load test the plan asks for, and excludes network, serialisation, queueing and database access. It shows the matching work is not the bottleneck; it does not show the service meets its SLO.
- **E8 — wishlist leakage** — Covers the response payload and the shadow topic. It cannot see leaks through timing side channels, through a real service's access logs, or through any surface this prototype does not have.
- **E13 — multi-match ranking** — Asserts the properties the ranking guarantees, not that the ordering is the one users would prefer. Which of three valid orderings performs best is a question for the experiment, and it has not been run.
